## 왜 이걸 만들려고 했나

부트캠프를 하던 작년에 친구들과 함께 시작했다가 팀원 모두 인턴으로 빠지면서 초반에 터진 프로젝트가 있다.
채용공고 데이터를 모아서 "지금 개발자 채용 시장에서 뭐가 요구되는가"를 분석하는 서비스였다.

아이디어는 단순했다. 취업을 준비하다 보면 이런 생각이 든다.

> "백엔드를 공부해야 하나, 데이터를 더 파야 하나, 지금 가장 많이 요구되는 기술이 뭐지?"

채용공고를 하나하나 들어가서 확인하는 건 너무 번거롭고, 몇 개 보다 보면 어디서 뭘 봤는지도 헷갈린다.
공고를 모아서 기술 스택, 연봉, 경력 요건을 정형화해두면 데이터로 답이 나올 거라 생각했다.

작년만 해도 없던 "AI Native Engineer" 같은 직군이 생겨나고, 몇 년 전엔 백엔드/프론트 분리가 기본이었는데
요즘은 혼자 다 할 수 있어야 한다는 공고도 많다. 시간이 쌓이면 이런 변화도 데이터로 보인다.

---

## 한 번 시도했다가 IP 밴 당했다

작년에 사람인에서 기존에 올라와 있는 공고 전체를 긁어오려다 IP 밴을 당했다.

bulk 크롤링의 전형적인 문제다. 짧은 시간 안에 너무 많은 요청을 보내면 사이트 측에서 차단한다.
당시엔 이걸 해결할 방법을 찾기 전에 팀이 해체됐다.

이번엔 전략을 바꿨다.

- **과거 공고 전체를 한 번에 긁어오는 건 하지 않는다**
- **매일 새로 올라오는 공고만 수집한다**
- **여러 사이트를 각각 크롤링하는 대신, 집계 서비스 단일 소스를 활용한다**

---

## 데이터 소스: 직행(zighang.com)

처음 설계에서는 점핏, 사람인, 잡코리아를 각각 크롤링할 생각이었다.
그런데 개발자 오픈채팅방에서 매일 올라오는 채용공고 알림을 보다가 **직행**이라는 서비스를 알게 됐다.

직행은 원티드, 로켓펀치 등 국내 주요 채용 플랫폼들과 정식 제휴를 맺고 공고를 집계하는 서비스다.
직업정보제공사업 신고 사업체이기도 하다. 여러 사이트를 따로 크롤링할 필요 없이 직행 한 곳에서 수집하면 된다.

단, 크롤링 시작 전에 확인해야 할 것들이 있다.

- `robots.txt` — 크롤링 허용 범위 확인
- 이용약관 — 데이터 수집·활용 허용 여부 확인

이 확인 과정도 다음 글에서 함께 다룰 예정이다.

---

## 무엇을 만들 건가

### 수집 항목 (공고 1건당)
- 회사명, 기업 규모
- 직무명, 카테고리 (백엔드 / 프론트엔드 / 데이터 / AI 등)
- 요구 기술 스택
- 경력 요건 (신입 / 경력 n년)
- 학력 요건
- 연봉 (공개된 경우)
- 공고 등록일

### 분석 목표
- 가장 많이 요구되는 기술 스택 순위
- 신입 / 경력별 요구 스택 차이
- 연봉 범위 분포
- 시간에 따른 트렌드 변화

---

## 기술 스택

부트캠프에서 썼던 기술들을 그대로 활용한다. 새로운 걸 배우기보다는 이미 아는 도구로 빠르게 만들고, 필요하면 그때 추가하는 방식이다.

```
[데이터 수집]
Python + requests / BeautifulSoup
소스: 직행(zighang.com)

[스케줄링]
Apache Airflow — 매일 오전 7시 자동 실행

[저장]
PostgreSQL

[백엔드]
FastAPI

[시각화 / 프론트]
초기: 블로그에 분석 결과 글로 게시
이후: 별도 대시보드 구성
```

---

## 개발 로드맵

| Phase | 내용 |
|-------|------|
| Phase 1 | 아이디어 정리 + 소스 전략 확정 ← 지금 여기 |
| Phase 2 | 직행 사이트 구조 분석 + 크롤러 구현 |
| Phase 3 | DB 스키마 설계 + 데이터 정제 |
| Phase 4 | 분석 쿼리 + 트렌드 집계 |
| Phase 5 | 시각화 대시보드 |

각 Phase마다 블로그 포스트로 과정을 기록할 예정이다.
이 글은 그 시리즈의 첫 번째다.
