## Claude Code 핵심 개념

Claude Code의 거의 모든 기능은 결국 다음 개념들의 조합이다.
이걸 먼저 잡아두면 나중에 어떤 예제를 봐도 구조가 보인다.

### 커맨드 (Command)

내가 직접 부르는 진입점이다.
`/review` 처럼 슬래시로 호출하면 미리 정의해둔 작업이 실행된다.
자주 반복하는 작업을 명령어 하나로 묶어두는 용도다.

커맨드 혼자서 모든 걸 처리하기엔 역할이 너무 많아질 수 있다.
그래서 실제 작업은 서브에이전트에게 넘긴다.

### 서브에이전트 (Subagent)

특정 역할을 맡아 작업을 대신 수행하는 보조 에이전트다.
"코드 리뷰 담당", "테스트 작성 담당" 처럼 역할을 나눠서 맡길 수 있다.
별도의 컨텍스트에서 일하기 때문에 메인 대화를 어지럽히지 않는다.

서브에이전트가 일을 잘 하려면 도구가 필요하다.
그게 스킬이다.

### 스킬 (Skill)

재사용 가능한 구체적인 기능 단위다.
에이전트가 작업할 때 꺼내 쓰는 도구라고 보면 된다.
한 번 잘 만들어두면 여러 에이전트가 같은 스킬을 반복해서 쓸 수 있다.

### 훅 (Hook)

정해진 시점에 자동으로 실행되는 동작이다.
"파일을 수정하기 전에", "작업이 끝났을 때" 같은 이벤트에 스크립트를 걸어둘 수 있다.
커맨드, 에이전트, 스킬이 흐르는 동안 특정 조건이 되면 자동으로 끼어드는 방식이다.

### MCP

Claude가 외부 서비스와 연동할 수 있게 해주는 프로토콜이다.
GitHub, Slack, Google Drive 같은 것들을 Claude가 직접 다룰 수 있게 된다.
에이전트가 필요한 정보를 외부에서 가져오거나, 외부에 결과를 보낼 때 쓴다.

### 플러그인 (Plugin)

커맨드, 스킬, 훅, MCP를 묶어서 배포 가능한 패키지로 만든 것이다.
팀 단위로 공유하거나 마켓플레이스에 올려서 다른 사람이 설치할 수 있다.

## 이 개념들의 관계

각각 따로 놓고 보면 비슷해 보이지만, 실제로는 역할이 다르고 계층이 있다.

```
[command]   내가 부르는 진입점
    ↓ 호출
[agent]     역할을 맡아 일하는 서브에이전트
    ↓ 실행
[skill]     에이전트가 꺼내 쓰는 기능
```

훅은 이 흐름과 별개로, 특정 이벤트가 발생하면 자동으로 끼어든다.
MCP는 에이전트나 스킬이 외부 서비스에 접근할 때 쓰는 통로다.
플러그인은 이 구성 전체를 묶어서 가져다 쓸 수 있게 한다.

## 참고 레포: claude-code-best-practice

개념을 잡았다면, 이걸 실제로 어떻게 엮어 쓰는지가 궁금해진다.
그때 참고하기 좋은 게 [claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) 레포다.
별이 5만 8천 개가 넘고, 커밋도 1,000개가 넘게 활발히 관리된다.
Claude Code로 만들어졌고, 그 결과물 자체가 베스트 프랙티스의 예시가 되도록 구성돼 있다.

부제가 _"from vibe coding to agentic engineering"_ 이다.
vibe coding은 그냥 Claude한테 "이거 만들어줘"라고 던지는 방식이고,
agentic engineering은 Claude가 언제, 어떻게, 무엇을 할지를 내가 설계하는 방식이다.
그 차이를 만드는 게 바로 앞에서 정리한 개념들이다.

### 레포 구성

주제별 디렉토리로 나뉘어 있다.

| 디렉토리                  | 내용                                      |
| ------------------------- | ----------------------------------------- |
| `.claude/`                | 실제 설정 파일 — agents, commands, skills |
| `best-practice/`          | 기능별 활용 가이드 문서                   |
| `orchestration-workflow/` | command → agent → skill 아키텍처 패턴     |
| `development-workflows/`  | 엔드투엔드 개발 워크플로우 방법론         |
| `tips/`                   | 개발자·커뮤니티가 모은 노하우 (83개)      |
| `tutorial/`               | 단계별 학습 자료                          |
| `agent-teams/`            | 멀티 에이전트 협업 예제                   |

### 어떻게 활용하면 되나

전부 따라 할 필요는 없다. 개념을 알고 나면 필요한 부분만 골라 보면 된다.

- `.claude/`에서 커맨드·스킬·훅이 **실제로 어떻게 작성돼 있는지** 본다
- `orchestration-workflow/`로 command → agent → skill을 **엮는 패턴**을 익힌다
- `tips/`에서 바로 써먹을 노하우를 줍는다
- 그중 내 프로젝트에 필요한 것만 가져와 적용한다
